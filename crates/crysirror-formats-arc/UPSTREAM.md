# arc_unpacker format plugins

This optional crate is **GPL-3.0-or-later**, translated from `vn-tools/arc_unpacker`.
Rust translation does not remove the original license. The shared
`crysirror-resource` API has its own MPL-2.0 implementation; opting into these
specific plugins is explicit. This document does not relicense a combined binary.
`LICENSE.md` reproduces the upstream GPLv3 license text. Source files retain the
upstream `Copyright (C) 2016 rr-` attribution and GPL SPDX identifier.

The complete reference checkout is kept in ignored
`local/reference/arc_unpacker`, not vendored verbatim. Its actual clean HEAD is
`456834ecf2e5686813802c37efd829310485c57d`, retrieved from
<https://github.com/vn-tools/arc_unpacker.git>. No game data, font, SDK, embedded
per-title key tables, or upstream binary fixture files are distributed here.

## Exact scope

The complete registration inventory is `upstream-formats.json`, regenerated by
`tools/inventory_arc_unpacker.py`. It contains **289 concrete decoder IDs**:
152 archive, 96 image, 16 audio and 25 file decoders. A plain source search finds
290 `register_decoder` occurrences because one is the helper template definition
in `src/dec/registry.h`. The five archive IDs below are registered in Rust: three
ported and two partial. The image registry additionally registers all 96 image
IDs (80 ported, 16 partial); 188 other decoders remain explicitly pending.
See docs/arc-image-support.json for the reviewed per-image variants and evidence. Inventory
membership does not imply implemented format or game coverage.

| Decoder ID | Implemented behavior | Boundary |
|---|---|---|
| `bgi/arc` | PackFile and BURIKO ARC20 tables; 16/96-byte CP932 names; relative entry offsets | Stable resource names retained; the CLI's guessed-extension renaming is not performed |
| `majiro/arc` | MajiroArcV2.000/V3.000; 32/64-bit hash table records, CP932 name table, absolute entry ranges | Versions outside the pinned decoder's 2/3 support fail |
| `nscripter/sar` | Big-endian SAR index, raw entry streams | No magic; structural probing is bounded to 256 KiB indexes; explicit format supports larger indexes. CP932 default or explicit UTF-8 filename codec |
| `nscripter/nsa` | Stored entries and MSB-first LZSS (256-byte zero dictionary, write position 239, 8-bit position and 4-bit length+2) | SPB image conversion is explicitly unsupported. Whole-archive keyed NSA is not implemented; callers can supply a separately transformed reader. Same probing/filename boundary as SAR |
| `kirikiri/xp3` | v1/v2; raw/zlib index; multiple raw/zlib segments; shuffled info/segm/adlr/time chunks; hnfn/eliF maps | Chained indices and unknown flags/chunks fail. Encrypted entries require a caller profile. No per-title decryptor or cxdec executable-code generation |

## Shared contracts and native semantics

Plugins consume `AssetReader` capabilities and return `Archive` instances.
Uncompressed ranges stay subreaders of the original stream. XP3 concatenates
segments in source order and uses the shared `zlib` transform per compressed
segment. NSA's format-specific LZSS reserves decoded memory through
`DecodeContext::decode_with` **before** allocating its output. Bounds, entry
counts, table sizes and resident decoded resources are checked.

Per-entry transforms come from the caller's client-scoped `PipelineSelector`,
`TransformRegistry` and `KeyProvider`. They run after segment decompression and
concatenation, matching XP3's original decrypt stage. Metadata carries XP3
`adler32`, flags, timestamp, segment count and both INFO size declarations.
An encrypted flag with no explicit transform profile fails visibly. Callers
may deliberately choose identity for the upstream synthetic no-op profile.
Neither XOR nor CTR authenticates a key; a wrong key is not detectable merely
from equal-length output. XP3 `adlr` is passed as metadata/key input and **is not
validated as a checksum**.

The original decoder reads file data from SEGM records, not the INFO declared
sizes. Its own compressed-file fixture puts decoded sizes in INFO's packed-size
field. This port therefore exposes actual segment sums as logical/stored sizes
and preserves INFO declarations separately. It does not reject that valid
upstream behavior based on an invented equality constraint.

Native filenames are decoded explicitly, then `ArchiveMount` performs the
shared canonical path/traversal/duplicate checks before exposing a VFS provider.
No unpacking subprocess, temporary extracted directory, device or native VM is
required to read an archive entry. Unknown resource layouts fail instead of
returning compressed/encrypted bytes as if they were decoded.

## Validation (2026-10-25)

- **Implementation:** the five concrete Rust archive decoders and the inventory
  above; no claim that the other registered upstream IDs are ported.
- **Compilation:** `cargo check -p crysirror-formats-arc` exited 0 on the local
  macOS host. Only safe CPU Rust code is introduced (`forbid(unsafe_code)`).
- **Ordinary behavior:** seven tests pass using archives generated entirely by
  the tests. They cover archive variants, CP932 names, native LZSS overlap,
  compressed indices and multi-segment reads, encrypted-entry profile/key
  scoping, malformed sizes, unsafe mount paths and resource limits. A synthetic
  100 MiB sparse archive entry is read with a 64-byte resident budget; indexing
  reads 48 bytes and subsequent entry reads remain random-access subranges.
- **External source corpus:** one explicitly invoked ignored test passes over
  14 upstream self-authored fixtures (seven XP3, two Majiro, two BGI, one SAR,
  and two NSA). It compares extracted paths/bytes to expected outputs declared
  by the original C++ tests, including their generated bitmap literal. No
  fixture binaries are copied here. **The original C++ executable was not built
  or run**, so this is source-corpus parity, not a C++ executable differential.
- Encryption coverage uses a clearly synthetic test key, not a game key.
  No proprietary installed-game archive or hardware/device result is claimed.

```sh
cargo test -p crysirror-formats-arc
ARC_UNPACKER_SOURCE=/absolute/complete/arc_unpacker \
  cargo test -p crysirror-formats-arc --test upstream_corpus -- --ignored --nocapture
python3 tools/inventory_arc_unpacker.py \
  --source-root /absolute/complete/arc_unpacker \
  --output crates/crysirror-formats-arc/upstream-formats.json
```
