# 0065 — Shared native resource codecs and owner-polled decode work

Date: 2026-10-26. Status: implemented scope; per-format variant limits remain explicit.

## Decision

Complete the named decoder migration from arc_unpacker at the inspected clean
commit `456834ecf2e5686813802c37efd829310485c57d`. The optional GPL plugin
contains binary layouts and native codecs; CrySirror owns the reusable resource,
image, audio-container, key, transform, task and VFS contracts. A VM is not needed
to use these capabilities. No unpacker executable, legacy renderer, game data,
font or title key catalogue is embedded. HCA uses safe Rust `cridecoder` 0.3.7;
no C/C++ codec runtime is linked. Plugin licensing remains as in ADR 0044/0046.

The inventory now contains 152 archive, 96 image, 16 audio and 25 file decoder
IDs. Explicit reviewed metadata distinguishes 258 ported from 31 partial
implementations. A registered parser and successful compilation do not establish
every native variant or title. The two ledgers document original-source gaps,
our bounded subsets, required host profiles and actual behavioral evidence.

## Shared ownership and APIs

`crysirror-resource` adds `FileFormat`, cloneable registries, `DecodedFile`,
`DependencyResolver`, parameterized `DecodeContext`, bounded output allocation,
LZSS, reusable crypto primitives and `WaveSpec`/loop serialization. Native keys
are client-scoped aliases resolved by the host. Title-specific executable
callbacks and copied secret tables are not project data. Generic transformations
remain usable independently of any particular format or VM.

`crysirror-image` owns deterministic checked PNG serialization, channel masks
and nontransparent pixel-copy semantics extracted from archive image formats.
Converted pictures feed the existing image/Bitmap/renderer path. Converted
sound resources feed the existing audio import/mixer path through shared WAVE
readers. No VM keeps a second general image/audio implementation.

`Resources` exposes file/audio discovery, bounded decoded-byte paging, VFS
publication and asynchronous decoding. `ResourceTasks` submits immutable reader,
registry, context and capability inputs to the existing bounded CPU pool. Opening
a provider-backed source also happens on the worker, so nested compressed files
do not decompress on the owner thread. Only
the owner polls a completion and publishes successful results. Cancellation
checks precede/follow a codec; a running codec can finish CPU work, but late
output is discarded. Retained ready/failed tickets count against 64/client and
256/host limits. There is no blocking join in status/read/publication APIs.

Ready results preserve their original context and resident-byte reservation.
Mounting clones the reader/archive ownership; cancelling the ticket does not
invalidate an already published resource. Synchronous `detectFile`, `readDecoded` and
`mountDecoded` are offline tools and fail in realtime hosts. Mounted archive
entries remain lazily decoded: realtime consumers use ordinary async Assets
loading rather than assuming all archive contents were decoded at mount time.
This is the resource subsystem boundary required by ADR 0050, not a claim that
all engine subsystems are now fully asynchronous.

Companion lookups stay under the same client's canonical VFS roots. The engine
holds a stable storage authority; provider contexts retain weak resolvers, so
mounting does not introduce a provider/resolver/VFS reference cycle. Host paths,
traversal, companion cycles/depth overflow, cross-client handles, missing key aliases and unsupported layouts fail
visibly. Profiles and task handles are runtime configuration, not portable save
content.

## Validation and limits

Implementation, compilation and behavior are recorded separately in STATUS.md
and the per-format ledgers. Self-authored fixtures test layouts, real cipher
payloads, malformed inputs, limits and ownership. External pinned fixtures are
read only at test runtime, require explicit ignored-test execution and are not
committed. Pixel comparisons follow the original tests' hidden-RGB rule where
both alpha values are zero; codec rounding exceptions remain documented.

WARC table-sized essential-cipher vectors are generated by compiling the pinned
original C++ functions using `tools/verify_arc_warc_cipher.py`. This validates
three portable math/cipher vectors, not whole-title encryption. Upstream's
negative-double-to-u32 expression is undefined in portable C++; Rust explicitly
truncates and wraps modulo 2^32. YLZ and other original-source unsupported
branches remain errors. Native profile requirements and restricted Unity/PSB,
palette, pickle and XP3 variants remain in the ledgers. No commercial game or
GPU rendering claim is made from codec-only validation.
